# Q4. The Three Pillars of LLM Success (Answers)

---

## Question 4.1

What are the three pillars of LLM success (DHA), and why must all three converge for LLMs to work?

---

**Answer:**

[*] Data — trillions of tokens of text from books, the web, code, and academic papers.
[*] Hardware — GPUs powerful enough to train on all that data efficiently.
[*] Algorithms — the Transformer architecture (2017) that processes text in parallel with self-attention.
[*] Remove any one pillar and modern LLMs would not exist: great algorithms on slow hardware with little data fails; massive data with a bad algorithm fails; best hardware with no good training objective fails.
[ ] Only the algorithm (Transformer) matters — data and hardware are secondary concerns.
[ ] The three pillars are: Data, Deployment, and Applications.

## Question 4.2

How much training data have recent LLMs used? What does the Chinchilla paper say about the optimal ratio of tokens to parameters?

---

**Answer:**

[*] GPT-3 (2020): ~300 billion tokens. LLaMA 2 (2023): ~2 trillion tokens. LLaMA 3 (2024): ~15 trillion tokens.
[*] 1 trillion tokens ≈ 750 billion words ≈ 7.5 million copies of the entire Harry Potter series.
[*] The Chinchilla paper (DeepMind, 2022) showed that tokens (data) and parameters (model size) must be scaled together for optimal performance.
[*] Optimal ratio: ~20 tokens per parameter. A 70B parameter model needs ~1.4 trillion tokens to be optimally trained. Most early LLMs were undertrained.
[ ] More parameters always produce a better model regardless of how much data is used.
[ ] The Chinchilla ratio is 1 token per parameter.

## Question 4.3

What are the five steps of the data cleaning pipeline, and why does "garbage in → garbage out" apply to LLMs?

---

**Answer:**

[*] Deduplication — remove duplicate web pages and repeated content.
[*] Filtering — remove low-quality, toxic, or spam content.
[*] Language identification — separate English from other languages for language-specific training.
[*] Domain balancing — ensure a healthy mix of code, science, conversation, etc.
[*] PII removal — strip personal information (emails, phone numbers).
[*] If low-quality data is used, the model produces low-quality outputs no matter how large it is — data quality matters more than raw quantity.
[ ] LLMs can correct for bad training data automatically during inference.
[ ] Deduplication is only needed for image datasets, not text.

## Question 4.4

Why are GPUs used for LLM training instead of CPUs? Use the "chef" analogy.

---

**Answer:**

[*] CPUs have few powerful cores (8–64), great for sequential tasks — like a few expert chefs cooking one dish at a time.
[*] GPUs have thousands of smaller cores (10,000+), great for parallel tasks — like thousands of cooks each doing one simple step simultaneously.
[*] LLM training is matrix multiplication at massive scale — exactly what GPUs excel at.
[*] Training GPT-3 required ~3,640 petaflop-days of compute, estimated at $4.6 million in GPU time — impossible with CPUs in any reasonable timeframe.
[ ] GPUs are used because they have more memory than CPUs.
[ ] CPUs are preferred for training; GPUs are only used for inference.

## Question 4.5

What is GPU memory (VRAM) quantization, and how does it allow LLMs to run on consumer hardware?

---

**Answer:**

[*] Quantization reduces the precision of model weights to use less memory: FP32 (32-bit) → FP16 (16-bit) → INT8 (8-bit) → INT4 (4-bit).
[*] A 70B model at FP32 needs 280 GB; at INT4 needs only ~35 GB — fitting in consumer hardware.
[*] Tools like llama.cpp and Ollama use quantization to run LLaMA 70B on a desktop with 48 GB GPU or a Mac with 64 GB RAM.
[*] INT4 quality is "good with some loss" vs full FP16 quality — a practical trade-off for local inference.
[ ] Quantization improves model quality by increasing numerical precision.
[ ] Quantization only works for models smaller than 7B parameters.

## Question 4.6

What is the difference between training and inference hardware requirements?

---

**Answer:**

[*] Training: extremely high compute, runs for weeks to months, requires thousands of GPUs, optimizes for throughput (tokens/sec), costs millions.
[*] Inference: moderate compute, runs in milliseconds to seconds per query, requires one to a few GPUs, optimizes for latency (time to first token), cost per token.
[*] This is why you can run LLMs on your laptop (inference) but cannot train one at home (training).
[*] Training modifies model weights; inference uses frozen (unchanged) weights to generate responses.
[ ] Training requires fewer GPUs than inference because it only runs once.
[ ] The hardware requirements for training and inference are identical.

## Question 4.7

What is the key idea of the Transformer architecture, and how does it differ from RNNs?

---

**Answer:**

[*] Transformer key idea: process all words simultaneously using self-attention — every word can directly attend to every other word in a single operation.
[*] RNNs process text one word at a time left to right, passing a hidden state — slow, not parallelizable, and "forgetful" over long sequences.
[*] Transformers are massively parallelizable (perfect for GPUs), capture long-range dependencies directly, and scale smoothly with more data and compute.
[*] The 2017 paper "Attention Is All You Need" introduced the Transformer for translation — but it soon proved applicable to virtually all language tasks.
[ ] Transformers process text sequentially but faster than RNNs.
[ ] Transformers require more memory per token than RNNs, making them impractical for long texts.

## Question 4.8

What are the five key innovations inside the Transformer architecture beyond self-attention?

---

**Answer:**

[*] Multi-head attention — multiple attention "views" in parallel, each head learning different patterns (syntax, semantics, coreference, etc.).
[*] Positional encoding — adds word-order information since attention has no inherent sense of sequence order.
[*] Layer normalization — stabilizes training by normalizing activations at each layer.
[*] Residual connections — skip connections from ResNet that prevent vanishing gradients in deep stacks.
[*] Feed-forward layers (FFN) — adds non-linear transformations after attention, processing each word independently.
[ ] Convolutional layers are the key innovation inside Transformers.
[ ] Transformers use hidden states passed between layers, like RNNs.

## Question 4.9

What are the three main Transformer architecture variants, and which one is used by most modern chat LLMs?

---

**Answer:**

[*] Decoder-only: predicts next token (autoregressive) — examples: GPT, Claude, LLaMA. Used by most modern chat LLMs.
[*] Encoder-only: understands input bidirectionally — examples: BERT, RoBERTa. Used for classification and understanding tasks.
[*] Encoder-decoder: maps input to output (sequence-to-sequence) — examples: T5, BART. Used for translation and summarization.
[*] Bonus: Mixture of Experts (MoE) activates only a subset of parameters per token — examples: Mixtral, GPT-4 (rumored).
[ ] Most modern chat LLMs use encoder-only architecture because it reads the full sentence before answering.
[ ] Decoder-only models cannot generate text — they are only used for classification.

## Question 4.10

What does the scaling law (power law) for LLMs mean, and why did it give companies confidence to invest billions?

---

**Answer:**

[*] As you scale up parameters, training data, and compute, the model's loss decreases following a smooth, predictable power-law curve.
[*] This predictability means researchers could estimate how much a larger model would improve before spending the money to train it.
[*] It gave companies confidence to bet billions on training ever-larger models because the outcome was mathematically predictable.
[*] Model sizes following the law: GPT-2 (1.5B, 2019) → GPT-3 (175B, 2020) → GPT-4 (~1.8T rumored, 2023).
[ ] Scaling laws are approximate guesses — performance improvements are unpredictable in practice.
[ ] The power law says that doubling parameters always doubles model accuracy.
